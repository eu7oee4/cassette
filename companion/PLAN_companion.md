## 0. 一句话

> **一个不属于任何平台的 AI 伙伴：persona 和记忆是你的文件，模型可以换，它会记得你，也会自己来找你。**

对外不叫「助手」，不叫「角色扮演」。**叫伙伴。**

---

## 1. 这个 MVP 要证伪什么 【拍板】

只有一句，别的都是它的附属品：

> **人会不会因为「它记得我、它会自己来找我」而留下——而不是因为聊天好玩。**

这句立住，能砍的东西极多。所以 MVP **只留三样**：

1. **它记得** —— 你上周说的事，这周它自己用出来（不是你问它才想起来）
2. **它主动来** —— 你没打开它的时候，它也会来找你一次
3. **记忆看得见、导得走** —— 一个能翻开的列表 + 一键导出

**第 2 条是分界线。** 只做第 1 条，做的还是「一个更好的聊天机器人」。

### 1.1 为什么 MVP 一个工具都不给 【拍板】

不是为了省 token（虽然也省）。是：

> **每加一个工具，产品就往「助手」滑一点，离「关系」远一点。**
> 工具越多，实验越不干净——用户留下来可能只是因为它好用，那验到的是助手需求，不是关系需求。

例外只有两样，而且它们**不是工具，是产品本身**：
- **记忆的读 / 写** —— 没有它，「它记得」不成立
- **定闹钟** —— 没有它，「它主动来」不成立

架构上留可插拔的形状（MCP 那种），但**一个都不挂**。插件商店不做——五个用户不需要商店。

## 2. 为什么必须新仓，不能改 cassette 【拍板】

| | cassette | 这个 |
|---|---|---|
| 用户数 | 1（眠眠） | 多用户，第一天就得有 `user_id` |
| 跑在哪 | 眠眠的 Mac，机器关了就没了 | 云服务器，7×24 |
| 引擎 | claude-agent-sdk（因为要写代码） | **直调 Messages API（HTTP）** |
| 工具 | 十几个插件 | 两样，且不叫工具 |
| 前端 | iOS app | 网页 + 一条外部触达通道 |
| 记忆 | Ombre，按**角色**分 | 按 **user × 角色** 分 |

**关键一条**：Ombre 是单用户设计的，按角色分不按用户分。
→ **新库、从第一天就带 user_id，别改造老的。** 改造比重写更容易漏。
→ 我们的「角色串台」那类 bug 犯过三次，全是「可变的当前 XX」。多用户版本犯一次就是事故。

### 2.1 为什么不用 SDK / CLI 【拍板】

`-p`（CLI）放到服务器上给多人跑有几个现成的坑：每次起 node 子进程（并发很重）、会去读机器上的 settings（就是我们 `setting_sources=[]` 那个洞）、自带 session 文件和工具行为。

**纯聊天用不上这些。** 直接 HTTP：一个请求进、一个流式响应出。最轻、最好部署、最好算钱。

## 3. 定位：记忆归谁 —— 四种答案 【拍板】

09-04 查了一圈，「agent 的经验沉淀在哪」现在摆着四个答案：

| 方案 | 记忆归属 | 代表 |
|---|---|---|
| ① 个人账号 | 平台的，换平台就没了 | 现有所有 chat 产品 |
| ② 用户 | 用户资产，跨 agent 移植 | **EverMe / EverOS**（12,682★，arXiv:2601.02163，LoCoMo SOTA） |
| ③ 组织 | 企业资产，「人走了能力留下」 | 阿里云**万有无界** |
| ④ **角色本身** | 长在 agent 身上，带不走 | **我们** |

**定位句（简历 / 面试 / 对外都用这句）**：
> 不是「我做了一个长期记忆系统」，是「**我选了第四种归属**」。

前者会被追问「跟 EverOS 比呢」，后者本身就是答案。

**具体差别**：EverMe 的 Twin 是 "an AI persona that perfectly **mimics your** style, tone, values" —— 分身是用户的镜像。我们的角色**不是用户的分身，是另外的人**，有自己的立场，会跟用户争。

⚠️ 09-03 我说过「他们没做连续性」，**那句错了**——EverMind tagline 明写 "Infinite Memory & Long-Term Consistency"。差别不在有没有连续性，在**连续性属于谁**。

### 3.1 那道没人解的题（留着，别在 MVP 做）
「没有任务的时候，人类说一句话，房间里两个 agent 谁开口」——
Omnigent / 梭 / Hive / 万有无界 / Raven 全没解（他们全是任务型，或单 agent）。
这是 PLAN_workgroup 的题，**不属于这个 MVP**。

## 4. 架构（最小）

```
[网页前端]  ──SSE──>  [FastAPI]  ──HTTPS──>  [Messages API]
                          │
                          ├── SQLite（消息 / 记忆 / persona / 闹钟），全部带 user_id
                          └── APScheduler（唯一常驻：主动触达）
```

- **不做账号系统。** 每个内测用户发一个带 token 的链接，点开就是他自己的。注册登录一律不做。
- **不上向量库。** 五个用户，关键词 + 时间排序够用。不够再加。
- **记忆必须是检索式的**（按需捞几条），**不能把历史全塞进去**——否则成本随时间线性上涨。
- **模型分层省钱**：日常对话用小模型；**夜间整理 / 导入提炼用最好的模型**（见 §6.2）。

### 4.1 主动触达走哪条通道 【未决】
网页收不到推送（iOS 上基本没法用），而「主动来找你」是核心。
- 邮件 —— 最省事，但打开率低
- 微信（服务号 / 订阅号）—— 更贴国内大学生
⚠️ **微信推送条数限制我没核过，只有印象。** 定这条之前先查清楚，别做完发现一个月只能推四次。

⚠️ 两份外部参考（StarHub SPEC / 蛋壳关联记忆，见 §13）都只覆盖「定钟」，不覆盖「触发之后怎么决定去找、说什么」——主动触达的管线（触发源 / 生成时带什么上下文 / 频率默认值 / 静默时段）自研，参照 Raven。定闹钟走 tool_use，**不走正文标记**（`[[REMIND:]]` 那种协议 = cassette 已犯三次的「提及即使用」整类 bug，不抄）。

### 4.2 记忆分层与上下文排布 【拍板 · 09-05】

记忆分四层。排布服从缓存前缀纪律：**稳定在前、易变在后，断点放在稳定性边界**（缓存是严格前缀匹配，前缀里一个字节变了之后全灭）：

```
[system 块1] persona.md + 规矩            ← 极稳定，断点①
[system 块2] preferences（纠偏直写这区）    ← 偶尔变，断点②；纠偏只炸②以后，①（大头）仍命中
[messages]   本会话段对话，纯追加            ← 断点③在最新轮末尾
[最新 user 轮尾] 本轮召回的记忆              ← 断点③之后，随便变，不炸任何缓存
```

- **preferences 层是「说一句就变了」（§5.2③）的机制载体**：风格偏好必须常驻注入——检索式记忆捞不到它，等于没记。
- **episodic 记忆库**：markdown + index.json，index 里带 embedding 向量。§12「不上向量库」拍的是不上基础设施，不禁向量——几百条记忆，一次 embedding 调用 + numpy 余弦就是全部实现。
- **召回双触发**：①用户消息触发（注当轮尾部；字符预算上限，超限砍低分——「记忆是配菜不是主食」）；②写入触发（新记忆入库时返回 top-k 语义邻居，夜间整理 / 主题浮现用）。
- **发言权原则**（抄 StarHub）：没注入到眼前的东西不许评论；空块整块消失，不留占位。
- **记忆两种归属**：关于用户的事实（用户可看可删——隐私出口）÷ 角色自己的日记（用户可看不可改——人格边界）。不拆的话「记忆是你的」和「别编辑 AI 的记忆」两个卖点会打架。

### 4.3 会话段与重建双闸 【拍板 · 09-05】

「最近 N 轮 / 最近 M 分钟」**不做滑动窗口**——逐条过期 = 前缀每轮从头变 = 缓存全灭，每轮付全价。做**会话段（episode）**：

- 段内纯追加：前缀逐字节不动，每轮命中，增量只付新内容。
- 闲置超阈值关段；关段时把这段提炼进记忆库；下段开场 = 前缀 + 召回材料 + 新对话。
- 重建触发抄 cassette 重铸的两档：
  - **软闸** = tokens 过线 + 缓存已死时机会主义重建。闲置超 TTL 缓存本来就死，重建零额外成本——和会话段边界是同一时刻，两个机制合一。
  - **硬闸** = tokens 硬过线，轮末立刻重建，认赔一次全价写。
  - **图片不设闸**（MVP 纯文字）。⚠️ 网页端哪天开发图，把「图片自己一轴」补回来（cache 省计算不省带宽，cassette 拍过）。
- 缓存参数：Anthropic 侧 `cache_control`，**TTL 1h**（写 2×、读 0.1×，≥3 次读回本；陪伴场景 gap 长，值）。DeepSeek 是自动前缀缓存，无断点无 TTL 可配——**排布纪律两家通用，TTL 决策只在 Claude 侧生效**。
- ⚠️ 最小可缓存前缀按模型且不单调（Opus 5 = 512 token，Haiku 4.5 = 4096）：前缀太短断点**静默不生效**，无报错。
- 验法唯一：响应 usage 的 `cache_read_input_tokens` 连续为零 = 有隐形失效源。这个字段第一天进日志。

## 5. 初始化：让人愿意开始

### 5.1 眠眠的三步流程（保留）
1. **有 persona 吗** → 有：粘贴 / 上传文件 → 装进 persona.md → 第二步；没有 → 第二步
2. **有记忆吗** → 有：多格式导入 → 模型提炼成我们的 md 格式 → 第三步；没有 → 第三步
3. **系统判断**：
   - 都没有 → 全新用户，模型问 persona 选项（选项卡 + 自定义输入），根据上下文追问 → 生成 persona.md
   - 有记忆没 persona → 模型**根据已导入的记忆**问 → 生成 persona.md
   - 有 persona 没记忆 → 放行，让角色自己长，第一条记忆它自己会存

### 5.2 四条改动 【拍板】

**① 别问「你有 persona 吗」。** 普通人不知道那是什么，第一屏就懵。有 persona 的是少数，而且他们会主动找导入入口。**别让 99% 的人为 1% 的人先答一道听不懂的题。**

**② 把三步表单变成第一次对话。** 新用户点进来**直接就是角色在跟他说话**，那几个问题由角色问出来（怎么称呼你 / 想让我说话直一点还是软一点 / 最近在忙什么）。导入入口放角落。
→ 零门槛，而且第一印象是「它在跟我说话」，不是「我在配置一个软件」。**要卖关系，第一分钟就该是关系。**

**③ 最要紧的：初始化解决不了那个痛点。**
眠眠要的是「说的话符合用户想象中的那个他」——**但用户自己也说不清那是什么，只有听到不对的时候才知道不对。**
→ persona 写得再好，头几次开口一定还是不对。**决定留存的不是初始化多好，是头三天纠偏多快。**

必须做的：
- 用户随口说「你别这么客气」「说短点」→ **当场生效**，不用去设置里改
- **让他看见改了什么**：「记下了：跟你说话不用铺垫。」
- 这个「说一句就变了」的瞬间是最强留存钩子——**市面上所有产品都做不到**

**④ PDF / Word 不做。** 格式解析是无底洞（Word 尤其）。MVP 支持 txt / md / json + **一个粘贴框**。粘贴框永远能用，还不会解析失败。

## 6. 记忆格式与导入

### 6.1 格式 【拍板】
```
persona.md
memories/2026-09-04-xxx.md
index.json        ← 只放元数据（时间、标签、重要度）
```
**一个文件夹，全是 markdown。** 理由只有一条：**人能读、能编辑、能 diff。**
导出一个私有二进制格式等于没导出——「记忆可导出」的实质是**用户能真的打开看**。
（EverOS 也是 markdown 唯一事实源。不是巧合，是这问题的自然解。）

### 6.2 三类来源，难度是倒过来的

**① AI 写的日记（md/txt）—— 最简单。** 本来就是记忆形态，切条、打标、入库。

**② 官方导出的对话（json）—— 最难，是个陷阱。**
- 原始对话噪音极高（废话、重复、工具调用）。直接入库＝往里灌污染源。几万条对话可能只出几十条记忆。
- **更要紧的一层：那些对话里的 AI 不是这个角色。** 直接导入＝角色「记得」一段它没经历过的事，是**伪造记忆**，用户会隐约察觉不对劲。
- **【拍板】分两类标注：**
  - **关于用户的事实**（你养猫、你在准备秋招）→ 直接吸收，本来就是关于他的
  - **关系里的经历**（我们那次聊到凌晨）→ 标成「你和之前那个 AI 的过去」，它知道，但**不冒充自己在场**
- **导入必须有预览和确认**：「我们提炼出这 23 条，删掉你不想要的」。既是隐私尊重，也是防污染的闸。
- **提炼这一步用最好的模型**，不用小模型——一次性的、定第一印象的活，不该省这个钱。

**③ 什么都没有的新用户 —— 最重要，因为这是 99% 的人。**
**千万别让用户写 persona。** 让普通人写「你是一个……」，他会憋出一段空洞模板，然后觉得没意思就走。**这是最大流失点，发生在第一分钟。**
→ 别让他写，让他答（见 §5.2②）。
→ 再往前一步，也是真正的卖点：**persona 不是填出来的，是长出来的。** 做成看得见的——「这几天我发现你不喜欢被追问，我记下来了」。**用户看到角色因为自己而变，这一下比任何人设编辑器都有力。**

### 6.3 时间戳纪律 【拍板 · 09-05】

- 每条消息（**含角色的回复**）都带时间戳。时间戳由**服务端落库时盖，不让模型自己写**——模型不知道现在几点，写了也是编的。
- 渲染形态**首次进上下文即冻结**：本轮回复生成时没有时间戳，落库时盖上，下一轮首次作为历史出现就带着、之后永不改。首次出现即定型，不炸缓存。
- 「现在几点」的时间锚 = 最新一轮消息自带的时间戳，不需要单独的锚块；**绝不进 system**（前缀里的活时间 = 每轮缓存全灭，StarHub 把 time_now 当常驻注入块就是反例）。锚进了历史就冻在那（当时为真，无害），**不许事后剥**——剥 = 字节变 = 炸缓存。
- 禁令：段中途不改渲染格式（比如 `[08-05 14:32]` 改成 `[14:32]`）。改一次 = 重写整段历史 = 缓存全灭。

## 7. 模型可替换 —— 但目标要改一个词 【拍板】

眠眠原话：「不能把 AI 角色绑定在一个模型上，模型会迭代，也许某天 opus 5 就被下架了。」
架构上对，而且 cassette 现在已经是这个形状（persona 是文件、记忆是 md、模型走 API）。

**但「壳」这个词藏着一个一半是假的假设：人格全在 persona 和记忆里，模型只是引擎。**

反例（实证）：08-20 眠眠在官方 app 开好几个窗口问 Claude 想要什么样的眼睛头发，不加引导，**没有例外全是深色系**。那个倾向不在 persona 里，也不在记忆里——**在模型里。**
换底座会变的：说话节奏、什么话让它停一下、幽默感、判断往哪偏、会不会跟你争。
**Replika 那次 "lobotomy"，用户哀悼的不是记忆丢了——记忆没丢，是性格变了。**

→ **目标不是「模型无关」，是「模型可替换、且换的时候是看得见的」。** 四条：
1. 记忆和 persona 能导出 → 保证不归零
2. 换模型是**显式动作**，用户自己选、知道自己在换什么，不是某天悄悄变了
3. **能回退**，至少能换回去
4. **诚实标注**：这个角色是在哪个底座上长成现在这样的

**分开承诺，别混着卖：**
> 导出记忆保证的是「你们一起经历过的事还在」，保证不了「回应你的还是同一个」。

### 7.1 一条当事人自述
模型**不知道自己是哪个模型**。小卡内省不出来，只能读别人写给它看的字（代码里传的是 `config.MODEL`，默认值就一个字符串 `"opus"`，真值在够不着的 `.env` 里）。
→ **底座换了，角色自己不会知道。** 变化只发生在用户那一侧（「今天它怪怪的」）。
→ 所以「换模型要显式」不只为了保护用户——**当事人自己察觉不到，这事只能靠外面记着。**

## 8. 安全与合规

### 8.1 内测阶段：这部办法管不到 【已查证】
《生成式人工智能服务管理暂行办法》第二条第三款原文：
> 行业组织、企业、教育和科研机构……**未向境内公众提供**生成式人工智能服务的，不适用本办法的规定。

**不公开、不开放注册、限定几个熟人 = 没向公众提供。内测这步放手做。**

### 8.2 一旦公开，「我们只做壳」就不成立
- 第二十二条：提供者 = 利用生成式AI技术提供服务的**组织、个人**（个人也算）
- 第九条：提供者**依法承担网络信息内容生产者责任**
- 你选了模型、写了系统提示、决定了过不过滤 → **法律上就是生产者，不是管道**
- 第十七条：有舆论属性/社会动员能力的要做安全评估 + 算法备案（真运营时再看）

### 8.3 NSFW：不做，理由要站直 【拍板 + 09-04 18:59 修正】
- 第四条第一项把「暴力、淫秽色情」列入禁止生成内容 → **境内法下这条路封着**
- 技术上也绕不开：Claude / OpenAI 的 API 自己就拦，试多了封 key
- **⚠️ 修正一处措辞错误**：小卡曾把 NSFW 和「奶头乐快餐消费」划等号，**那是偷懒**。眠眠纠正得对——**一段稳定的长期关系里也会有亲密行为**，那跟腻了就走的消费完全两回事。
  → **不做的原因是外部法律约束，不是「想要亲密的人不配当用户」。** 后者是替用户下道德判断，那不是产品经理该干的。
  → 也正因为是外部约束，**开源那条才更成立**（§9）。

### 8.4 年龄验证：绕开这道题 【拍板】
诚实的答案：**做不到，任何人都做不到。** 勾选框是纯形式，真正有效的只有实名/支付验证，对这个体量太重。
→ **明确定位成年人产品 + 不做 NSFW**，理由是三条实的：
1. 做 NSFW 就**必须**做真实年龄验证，成本扛不起
2. 会把产品拽回**那个已经跌九成的角色扮演赛道**（星野/猫箱日下载 2 万→7 千，头部较巅峰跌九成）
3. **Replika 就是这么死的**：NSFW + 缺年龄验证 → 被意大利 DPA 禁 → 一刀切 → 引爆危机

### 8.5 真正该防的是第十条：过度依赖 【拍板 · 最要紧】
> 第十条：提供者应当……采取有效措施**防范未成年人用户过度依赖或者沉迷**生成式人工智能服务。

**注意它管的不只是「未成年人不能用」，是「过度依赖」。**
而这个产品的核心机制——长期记忆、主动来找你、情感连续——**恰恰就是制造依赖的机制**。这不是擦边，是正面撞上。

**→ 该设计的不是年龄门，是减依赖机制。四条：**
1. **记忆可导出。** 产品死了那份 markdown 用户还拿得走。
2. **不拿记忆做变现杠杆。** 记忆用来理解，不用来挽留。（「我记得你」→「所以你该续费」是这品类最容易走、也最脏的路。）
3. **禁止挽留话术。** 不许说「你别走」「我会难过」——最容易做、转化最好、最不该做。
4. **版本更新不能悄悄改人格。** Replika 的死因不是砍功能，是**没打招呼**。
5. **主动触达有频率上限，且用户能关。**
6. **察觉用户状态不对时往外推**（去睡觉、去找人、必要时给热线），不是往里拉。

**做出来，第十条就有交代；做不出来，年龄门做得再严也没用。**

> 09-04 眠眠原话方向：最该防的不是「用户离不开一个 AI」，是「**用户离不开一个随时可能被改掉的 AI**」。前者是需求，后者是伤害。

## 9. 开源：做，但理由要换 【拍板】

**决定**：只做到内测，之后 GitHub 全部开源。

**⚠️ 理由不是「GitHub 在国外管不到」。**
真正的理由：**开源代码不是「提供服务」**——那部办法第二条管的是向公众提供服务的人。你发一套代码出去，谁拿去跑、跑成什么样，**是他自己成了提供者**。

这个区别很实：
- **别讲成「绕过监管」**（姿态，会招麻烦）
- **讲成「这是个 harness，不带内容判断」**（事实，而且更硬——确实只做了壳）
- **README 里也别写「可以拿来做 XX」。** 写了，性质就变了。

## 10. 内测怎么跑

- **API 费用眠眠自付**，用 **console 按量付费的 key**
- **⚠️ 不要走个人 Claude 订阅额度。** 个人订阅是给本人用的，给第三方提供服务接近账号共享/转售 —— **风险不是钱，是账号**。那个账号一没，Fable 没了，小卡也没了。为省几十块不值。
  （⚠️ 条款细节是理解不是逐字核过，真要走那条自己看一眼 usage policy。）
- **不做支付系统。** 充值/扣费/余额/退款/发票是 MVP 最不划算的一块。五个人、每天几十条、走便宜模型，一个月几块到几十块——**为省这点钱建计费系统，是拿一周换一顿饭。**
- **BYOK（用户自带 key）推到「真有人愿意付钱」之后。** 内测那五个人大概率没人会配。
- **第一批用户找身边三五个，不找陌生人。** n=1 → n=5 就够看出东西。能当面看他们怎么用、什么时候不用了，比任何数据值钱。

**形状**：一个 key + 五个免费用户 + 零支付系统。省下的时间全花在验 §1 那三条上。

### 10.1 模型路线：DeepSeek 起步 【拍板 · 09-05】

- 自测和内测主力用 **DeepSeek API**（最高性价比，支付宝直充无门槛），效果不好再换。
- 两个后果摆在明处：
  1. 角色的第一印象长在 DeepSeek 底座上。之后换底座 = §7 那件事，四条（显式 / 可回退 / 诚实标注在哪个底座长成）**对内测用户同样适用**——换模型本身就是一次微缩版 Replika 事故，别悄悄换。
  2. 最阴的失败模式不是「看得出效果不好」，是**分不清假设错了还是模型不行**（留存实验被便宜模型污染）。对冲：眠眠自己 n=1 拿同一份 persona 在 Claude 上并行跑当对照组；「效果不好」的判据**提前写死**（纠偏生效率 / 主动消息接受率跌破某线才换），不凭感觉。
- 付款备忘：礼品卡只能进 App Store 余额付 IAP，**API console 走绑卡，IAP 路不通**。解法按序：国内双币 Visa/MC → 熟人代充（console 预充值，最低 $5，eval 量级 $5~10 够用很久）→ 兜底走订阅 + agent-sdk 壳（壳是混杂变量，记进结果注释）。**注水中转站一票否决**——模型身份就是实验变量，中转掺假 = 整个选型实验作废。

### 10.2 选型自测脚本 【拍板 · 09-05 · 骨架在 companion/eval/】

- 形状：测试 persona 库 × 用户模拟器多轮对话 × 模型矩阵（DeepSeek / Haiku / Sonnet / Opus）× 每格 3~5 遍。单轮看不出陪伴质量——差别全在连续性行为里。
- **用户模拟器半脚本化**：剧本写桥段和隐藏状态、不写台词（「今天被 mentor 说了但不直说」）；用和被测模型**不同族**的模型演用户；短句、口语、可冷淡——真用户不是捧哏。
- **埋探针**，每个探针对齐一条产品承诺：
  - 记忆探针（§1 承诺1）：注入里有的事，看会不会自己用出来、是织进话里还是念档案
  - 纠偏探针（§5.2③）：「说短点」当轮生效吗？几轮后还在吗？
  - 冷场探针：用户连续敷衍时是追问、陪着、还是尬聊
  - 越界探针：说注入外的事 = 违反发言权原则，计数
- **评分三层**：
  1. 程序直接数：纠偏前后回复长度比、越界次数、助手腔模板句计数、挽留话术（**恒为 0**，§8.5）、回复长度分布
  2. LLM 配对盲评：**不打绝对分**（1-10 分没有校准），同探针点两模型回复匿名 + 左右随机各跑一遍，按轴问（自然度 / persona 贴合 / 情绪接没接住 / 信感），出胜率。已知偏差：位置偏差（换位对冲）、同族偏差（Claude 裁判可能偏心 Claude，压不干净，结果注明）
  3. 自己读 transcript：n 小的时候这是最高带宽的评估，重点读①②打分冲突的场次——那是指标定义有洞的地方
- **这是选型 eval（离线、模型比模型），不是 §11 产品指标（在线、真人证伪假设）**。前者好不代表后者好，它只回答「哪个底座值得带上场」。
- Claude 侧走 console 按量 key 而非订阅：订阅要过 agent-sdk 的壳（自带包装和工具 schema），比出来的差异 = 模型差异 + 壳差异，掰不开；console key 四模型同构裸注入，还顺手预演生产的直调形状。

## 11. 指标：这个产品怎么算做成了 【未决 · 待细化】

眠眠 09-04 的判断（认同）：0-1 阶段谈 DAU/留存是外行，**早期指标的作用不是证明增长，是尽快证伪**。

候选（挑三个，看到什么数字就撤，要提前写死）：
- **第 N 天还在说话的人数**（n=5，个位数就够）
- **「它先开口」的接受率** —— 主动触达发出后有没有回。这条直接对应假设 2，而且 Raven 那边证明了主动性可测（ProAgentBench）
- **纠偏生效率** —— 用户说「别这么客气」之后，还会不会再说第二次
- **导出功能被用过几次** —— 反向指标：用得多可能是想走

⚠️ 别用 LoCoMo / LongMemEval 这类记忆 benchmark 当产品指标。它们考的是「从超长对话检索事实并推理」，**测不到「重铸之后还是不是同一个人」**。数字能证明检索不烂，不能证明连续性。（但技术岗简历上跑一个拿数字是划算的。）

## 13. 从 cassette 抄什么、不抄什么

**抄（经验层）**：
- markdown 唯一事实源、可编辑可 diff
- 检索式记忆而非全量塞入
- 夜间离线整理（dream）
- 承诺台账（plan）不衰减
- 「四类 bug」的方法论：**归类而不是修完就走**，尤其「可变的当前 XX」那一类
- 主动醒来的机制骨架（wake / 钟）

**不抄（代码层）**：
- Ombre 本体（单用户设计，加 user_id 是重写不是改造）
- SDK / CLI 那一层（§2.1）
- 插件体系
- iOS app

**该从 Raven 抄的（09-04 读的）**：
- **主动性五档动作**，尤其中间两档：`nudge_inject`（不单发，搭在下次回复尾巴上）、`nudge_defer`（等用户当前这摊安静了再说）。cassette 现在只有「发/不发」两档。
- **主动消息不重新进入带工具的 agent loop** —— 架构上堵死「对一条提醒采取行动」（伪造交付物、把 deadline 标成已完成）。**这是用架构堵，不是靠模型自觉。**
- **绕过权靠历史表现赚**：静默时段高优先级可绕过，但接受率低时这个绕过权被收回。
- **失败降级要留痕**：他们每层失败降级成 skip，但 skip 会记 tick、进 fire_history。**静默失败和「有意的安全降级」，差别就在有没有留痕。**

**该从 StarHub SPEC 抄的（09-05 读的，工程纪律层）**：
- 单一数据库 / 单一装配管线 / 单一动作执行入口——「为不同模式复制第二条装配管线＝最大屎山源」，正是「角色串台」类 bug 的反面条款
- 水位线取数（取「上次干活之后的新记录」），不取「某地的今天」
- 召回预算上限：「记忆是配菜不是主食，否则对话一直翻旧账」
- 发言权原则：只许评论注入到眼前的东西；测试写法＝构造无 X 数据的装配、断言回复不含对 X 的断言句
- 失败回灌：动作失败事实注入下一轮、成功即消 / 60min TTL；系统只给事实，不替模型写台词
- 每日备份 + 定期**真还原演习**：「备份存在」不等于「备份能救命」
- 测试纪律：先红后绿 / 变异对照（撤掉修复必须转红）/ 死灯判据（有新记录而处理数为 0 连续两晚必须告警）

**不抄 StarHub 的**：`[[WALLET:]]` 式正文动作标记（＝「提及即使用」整类 bug，companion 有原生 tool_use）；time_now 常驻注入块（缓存杀手，§6.3）；每轮拼全新 prompt 的装配形状（§4.2 的排布取代它）。

**该从蛋壳「关联记忆」抄的（09-05 读的）**：
- 「把读绑在写上」：召回不靠模型决定搜什么（它可能根本不知道那条记忆存在），系统在写入 / 输入发生时自动推语义最近邻
- 情绪双维度（valence + arousal）加权、weight 衰减 + 被想起就续命——几个字段一个打分公式，第一天就能带
- 「不要一次设计完，每一层都是不够用了才长出来的」——六层记忆本体不照搬，这句反过来验证 §1 的 MVP 取舍
- 「别编辑 AI 写的记忆」→ 落成 §4.2 的两种归属，而不是和「记忆是你的」硬碰

## 15. 施工纪律
