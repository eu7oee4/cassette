# workbench：网页工作台（通用交付层）

把任何领域的成果（面试手册、学习计划、项目清单…）做成**可勾选、可笔记、进度存得住**
的网页。它跟领域无关：内容从哪来是域 skill（如 jobhunt）的事，这里只管交付形态。

## 铁律

1. **先拷问，再动工。** 没过 `prompts/grill.md` 的需求不开工——「一句话让 AI 做网站」
   做出来的东西九成不是对方要的，返工比拷问贵得多。
2. **进度文件是用户资产。** 勾选和笔记是人花时间留下的——改版工作台**必须迁移**
   已有进度（见 `prompts/progress.md` 的 id 稳定规则），清零 = 事故。
3. **自包含单文件。** 一个 HTML 装下全部（内联 CSS/JS，无 CDN、无外链）——
   在 app 里能看、拷走能开、将来要托管拿着文件就走。
4. **敏感信息不进页面。** token/密钥/授权码/联系方式一律不写进 HTML——
   页面会被存盘、传送，它不是私密载体。
5. **禁 `innerHTML` 塞变量**（XSS 纪律）；动态内容一律 `textContent` / DOM API。
6. **一页只有一个「保存」动作**，数据流单一（抄 agent-html-skills 的 Submit 纪律）。
7. **每个工作台带一份工程档案** `state/workbench/<slug>/PLAN.md`（结构见 build.md）：
   需求定案、分期、待优化、施工记录都在里面。新建先立档，改版先读档，收工必写一行
   施工记录——没有档案的工作台，下次改版就是从猜开始。

## 路由表

| 场景 | 读哪个 |
|---|---|
| 新工作台，需求还是一句话 | `prompts/grill.md`（拷问出需求定案，再往下） |
| 需求定了，开始搭 / 改版 | `prompts/build.md` |
| 进度怎么存、怎么回流、改版怎么迁移 | `prompts/progress.md` |
| 视觉与排版（搭之前必读） | `frameworks/ui-style.md` |

## 模式库（patterns/）

进度头 / 勾选清单板块 / 笔记卡 / 折叠详情等可复用 HTML 模式——**还没长出来**：
按计划（PLAN_skills S5）从第一个真实工作台倒推。在那之前 build.md 里现写，
写完值得复用的块记下来提给机主，别提前编一套没验证过的模板。
