# build：搭 / 改版工作台

前提：需求定案已确认（`prompts/grill.md`）；`frameworks/ui-style.md` 已读。

## 工程档案（PLAN.md，铁律 7 的执行面）

每个工作台一份，`state/workbench/<slug>/PLAN.md`（slug 用人话短名如 `jobhunt`，
不用 page_id 那串哈希）。文体照主仓 PLAN_*.md 的家风：方案+拍板+施工记录一体。

```
# <名> 工作台
部署：page_id = <webpage 的 id>
## 需求定案     ← grill 的产出原样落这儿；需求变了先改这儿再动工
## 分期         ← 一期做了什么 / 二期想做什么（拍过板的才算数）
## 待优化       ← 只记问题和现象，**不记方案**——方案要等拍板，免得半个主意被当成决定
## 施工记录     ← 一行一版：日期 + 改了什么；最后一行就是当前进度
```

- **新建先立档**（需求定案确认后第一件事），**改版先读档**，**收工必写施工记录**。
- 档案是给 TA 和机主看的工程日志，别写进页面（页面那份「更新记录」是给看页面的人的
  一句话版，两份各管各的受众）。

## 流程

0. **立档/读档**：新建 → 建 PLAN.md 落需求定案；改版 → 先读 PLAN.md 和「待优化」。
1. **收内容**：从域数据文件收齐这版要呈现的全部内容（如 `state/jobhunt/manuals/…`）。
   内容缺口回给域 skill 补，**不在搭页面时现编内容**。
2. **定结构**：按需求定案画板块清单（顶部进度头 → 各板块 → 底部保存/导入导出区）。
   每个可勾选项在这一步就定下**稳定 id**（见 progress.md——id 定错，改版就迁不动进度）。
3. **写页面**：自包含单文件 HTML（SKILL.md 铁律 3/4/5）。手机 webview 优先：
   单列、系统字体栈、点击区 ≥44pt、不横滑。
4. **接进度**：照 `prompts/progress.md` 接 localStorage + 导出/导入；有落盘端点就接端点。
5. **交付**：
   - chat/wake：`webpage_write`（app 里直接能看；改版用同一个 page 覆盖，别开新页）。
   - code 会话：直接写文件也行，但最终仍走 webpage 交付——机主在 app 里看，
     不是在电脑上开文件。
6. **自验**：过一遍需求定案的验收场景 + 「勾两项 → 刷新 → 还在」。
7. **归档**：PLAN.md 写一行施工记录；发现但没做的事进「待优化」。

## 改版（已有工作台）

- 先读 PLAN.md（需求定案还作不作数、待优化里有没有这次该捎带的），
  再 `webpage_read` 拿现版，**读懂再动**——尤其进度接线和 id 清单。
- id 不许变（progress.md 的迁移规则）；删板块要在页面上留「已归档」痕迹而不是凭空消失。
- 改版说明写进页面底部的更新记录（一行日期 + 改了什么），机主看得出版本变化。
