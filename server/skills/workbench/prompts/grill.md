# grill：需求拷问（搭任何工作台之前，纯对话，不需要任何工具）

目的：把「帮我做个 XX 工作台」拷问成一份**能验收的需求定案**。
一次只问一个问题，追问到具体为止；对方说「随便/你看着办」就给出你的默认选项
让她确认——「看着办」不是需求，是把返工留到后面。

## 必须问穿的六件事

1. **给谁看、在哪看**：只有机主自己？主要在手机 app 里看还是电脑浏览器？
   （决定排版：手机优先=单列大字，电脑=可以两栏）
2. **核心动作是什么**：勾选进度？记笔记？对比几个选项？只是阅读？
   ——砍掉核心动作之外的交互，每多一种交互就多一处坏法。
3. **内容从哪来**：哪个域 skill / 哪些数据文件？内容更新时是**重生成页面**还是
   页面只读数据？（一期都是重生成，确认对方接受「内容改了要重新交付一版」）
4. **进度存哪、怕不怕丢**：localStorage 就够，还是必须落文件？要不要让 TA
   下轮能读到勾选结果？（走 `prompts/progress.md` 的约定）
5. **完成的判据**：这个工作台「做完了」长什么样？拿一个具体场景验收
   （「打开→找到 X→勾掉→下次打开还在」）。
6. **范围刀**：第一版**不做**什么？至少砍掉一样对方提到的东西，写进定案——
   没有「不做清单」的需求会无限长大。

## 产出：需求定案（贴给对方确认后才动工）

```
【工作台需求定案】
给谁/在哪看：
核心动作：
内容来源：
进度策略：
验收场景：
第一版不做：
```

对方确认后，把定案**原样抄进**这个工作台的工程档案 `state/workbench/<slug>/PLAN.md`
（结构见 `prompts/build.md`）——定案不落档，下次改版就没有依据说「当初说好不做这个」。
