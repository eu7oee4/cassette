# company-intel：公司深扒（草稿版，跑完第一家后回来修）

产出：`state/jobhunt/intel/<公司名>.md`，一家一个文件。手册（interview-manual）和
反问清单都从这里取材——**先扒情报再写手册**，顺序不能反。

## 开工前

- 读 `frameworks/evidence-ranking.md`——每条信息都要落「来源 + 档位 + 日期」。
- 看 `intel/` 里有没有已经扒过的（铁律 2：先查库）。有就增量更新，别重扒。

## 扒什么（按优先级）

1. **业务是什么**：官网 / 官方公众号 / 产品本身。能亲手用一下产品最好——
   面试里「我用过你们的 X，发现…」是最硬的开场素材。
2. **这个岗位在业务里干什么**：从 JD 反推——它属于哪条产品线/哪个环节，
   招这个人是去解什么问题的。这一条是手册「岗位匹配」的地基。
3. **创始人/核心团队**：背景、公开访谈、近期动向。小公司尤其重要——面你的
   很可能就是本人。
4. **口碑**（inferred 档，只当背景不进硬判断）：小红书、脉脉、面经。
   浏览器插件带登录态，小红书直接搜「<公司名> 面试 / 工作体验」。
5. **近况**：融资/裁员/新产品（近一年）。

## 产物结构（intel/<公司名>.md）

```
# <公司名>
更新：<日期>

## 业务         （每条带 [档位·来源·日期]）
## 岗位在业务里的位置
## 团队/创始人
## 口碑（inferred，仅背景）
## 近况
## 反问素材      ← 扒的过程中随手记：值得当面问的点
## 待查          ← unknown 的先记这儿，不许猜
```

## 纪律

- 扒不到就写进「待查」，**不许用行业常识补位**（evidence-ranking 规则 2）。
- 口碑帖的负面信息记下来但降档处理——一条匿名帖不构成判断，三条独立同向才算 partial。
