# story-mining：把一件真事挖成能讲的故事（草稿版）

两种进来的方式：**手册里发现「这题没素材」**（去库里/记忆里找一件真事来填），
或者**刚发生一件事**（今天修了个 bug、扛过一次事故），趁热挖。

产出落 `state/jobhunt/stories/<slug>.md`，并在 `stories/_index.md` 记一行
（一句话摘要 + 能答哪几类题）——同一件事以后几个岗都能复用，别一岗重挖一遍。

## 核心：讲的不是「我做了什么」，是「我从中拿走了什么能迁移的」

一件事本身有没有技术难度，**不是它能不能讲的判据**。
判据是：**你有没有从它身上取出一个能带走的东西。**

> 有血的一条（2026-08-28）：机主修了个「角色 A 的设置被写进角色 B」的 bug。
> 第一版讲稿写的是「我怎么定位的：比文件 mtime、比字段」——被她自己否了，原话是
> 「这事本身怎么找哪错了没什么技术难度，而且也不是我找的」。
> 重写成「这属于哪一类通用错误 / 下次怎么规避 / 我拿这个类去扫了全仓，还有几处同类」
> 之后才立住。**同一件事，换个取角，从没得讲变成主打。**

## 三条纠偏（每条都是踩过的）

1. **不许为了让故事好听而改事实。**
   把「没报错」写成「数据看起来完全正常」——多出来的那半句是编的。故事里每一个细节
   都得是当时真发生的。铁律 1 在这里同样生效，而且更容易犯：编故事细节比编数字隐蔽。
2. **不许凹金句。** 冒号、破折号、三段排比——那种句子是写给人夸的，不是说给人听的，
   而且一眼就是 AI 写的。**写完念一遍**：这话你在饭桌上会这么说吗？不会就重写。
   考场句要短、要像人话，可以不工整。
3. **归属诚实，反而加分。** 「这个是 AI 帮我找的，但我看完之后发现……」比假装自己找的强。
   面试官分得清「会用工具」和「用完就走」，后半句才是他们要买的。

## 挖的时候用的钩子（现场问机主，一次一个）

先问事实，再问反事实。反事实才挖得出决策——**没被选中的那条路，比选中的那条更能说明
你在想什么。**

- 当时你差点选了哪条路？为什么放弃？
- 如果不这么做，最坏会怎样？（问「代价」比问「收益」诚实）
- 这事重来一次，你哪一步会不一样？
- 有没有哪一刻你是不确定的？怎么处理那个不确定的？
- 这里面哪一部分是你想出来的，哪一部分是别人/工具给的？
- 你后来有没有在别的地方又见到过这个问题？

追问到**具体**为止：具体的时间、具体的判断、具体的那句话。含糊的回答不写进库，
写 `待补`，下次接着问（铁律 1）。

## 一个故事立不立得住，看这几样（参考，不是清单）

不用凑齐，凑不齐也别硬编——有两三样扎实的，就已经比一个面面俱到但空的故事强：

- **真实的代价或难度**——比如这个坑难触发，那本身就说明你是真的在长期使用和维护它，
  不是做完就扔（这条经常被低估，它证明的是「持续投入」，不是「技术强」）
- **能归类**——你说得出它属于哪一类问题，而不只是这一次的具体情况
- **能迁移**——说得出下次在别的地方怎么躲
- **有后续动作**——不是嘴上反思，是真的去做了点什么（扫了同类、加了规则、改了流程）
- **有取舍**——你放弃了什么，为什么

还有别的角度也算数：预判对了一件事、坚持了一个不受欢迎的判断、及时承认了自己错了。
不在上面这张表里不代表不能讲。

## 落库格式

```
# <一句话标题>
- 能答哪几类题：主标 1 个 + 副标 1–2 个，标签取自 `frameworks/competency-tags.md`；再列几道具体题
- 时间与背景：（真实，一两句）
- 我的判断与取舍：（重点，最长的一段）
- 结果：（有数字写数字，没有就写没有，不编）
- 我从中带走了什么：（这条是故事的轴）
- 口述版：（120～200 字，念一遍像人话的那版）
- 待补：（还没问到的）
```
