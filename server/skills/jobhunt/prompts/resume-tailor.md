# resume-tailor：决定投了，出这家的定向简历（草稿版，跑完第一个岗后回来修）

前置：**先有 jd-decode 产出**（Must Have + 隐藏信号），没有先跑一遍。
产出：一个定向版 `variants/<公司>-<岗位>.md` + PDF。**只出一版**——国内投猎聘和 Boss，
机器筛简历那套不是主战场，三版本是浪费。

## 铁律（这篇最容易犯的是铁律 1）

- **绝不杜撰。** 只能基于母版里**已有的事实**重新组织、突出、翻译话术。
  ❌ 编新成就 / 新数字 / 新职责；❌ 把「参与」改成「主导」；
  ✅ 把「做了 X」翻成 JD 的措辞习惯；✅ 已有数字换个角度呈现。
  数字、影响范围、头衔一律向机主求证，**她没说的不写**。
- **外部验证类条目（star / 奖项 / 被引用 / 专利 / 著作权）写进去之前必须点开原始出处确认署名是她。**
  有血的一条（09-01 21:33）：`AI产品-通用版` 曾抄进「drift-bottles-skill 26 star」，那是别人的仓。
  档案是索引不是事实源。
- 动母版前必读 `PLAN_jobhunt.md` 顶部五条；母版只有她明确同意才动。

## Step 1 · 收齐输入

`resume_read("master")` 全文（不是摘要）；jd-decode 的产出；`profile_get` 里「简历现状」和
「写法口味」两节；机主想强调的一两个亮点（没说就按 Must Have 命中最强的挑）。

## Step 2 · 先定策略，再动笔

动笔前先告诉机主，**她认了方向再改**（避免改完她说「我不想突出这块」）：
1. 这份 JD 的 **3 个关键词**（从 Must Have 抽，要在简历里反复出现的）。
2. **1 条核心叙事**（整份简历围绕的那句话，如「从真实使用出发定义 AI 产品形态」）。
3. 哪些段**重写 / 重排 / 弱化 / 压成一行**。

## Step 3 · 出定向版

- 句式：**「面对什么 → 做了什么判断 → 推动了什么 → 结果是什么」**，不是罗列动作。
- 最相关的经历置顶；每段前一两条要点直接对齐 Must Have；不相关的早期经历压成一行。
- 隐藏信号对应的特质具体化（JD 强调 0-1 → 把「从零定义」那段写实）。
- 保留一两个有故事感的细节——面试官会追问这些，那是入口不是漏洞。
- **写法口味（档案 09-01）**：不写卖弄的话（「我是它唯一的产品经理也是每天在用的用户」打回，
  同样信息用事实句：「唯一用户就是自己，每个功能都源自真实使用里撞到的问题」）；
  项目条目只写清架构和特点，**「为什么这么做」别写满，留给面试官挖**。
- 日期口径：cassette 建仓 2026-08，**不写「数月」「长期运行」**，对两行日期就穿。
- 产品线 vs 开发线用词不同：产品线写「定义了什么形态、为什么这么定」，开发线写「实现了什么」。
  按 jd-decode 判的岗位类型选，别混。

## Step 4 · 逐条 diff + 对齐说明（核心体验，不许省）

改了几条给几条，不只给终稿。每条：

```
【改动 #1】
原文：> …
改后：> …
对齐了：Must Have #1（…）· 隐藏信号（0-1）
依据母版事实：「…」
```

看得到「为什么」下次她才会自己改。

## Step 5 · 自陷检查（每一句都过）

简历里每句话面试官都可以无限追问。改完逐句问：**被追问扛得住吗？**
- 数字：口径说得清吗（怎么算的、分母是什么）？
- 「主导」：具体主导了哪一段，队友各做了什么？
- 技能：经历里有没有一处真用到？没有就删，别引追问。
扛不住的两条路：改保守（「主导」→「负责其中 X 模块」），或者记进手册「可能追问」提前准备。
**不选第三条路「赌他不问」。**

## Step 6 · 落库

- `resume_save(content, resume_id="<公司>-<岗位>", jd_id=…, note=改了什么)`——id 起中文人话名
  （沿用 `猫太-产品经理` 那套），**不留空自动编号**，名字要自己说清能不能投。
- `resume_render(resume_id)` 出 PDF，渲完看一眼页数。给自己看的注记别指望渲染层剥掉。
- 告诉机主：这版对应哪个 JD、改了几条、两处留白（Figma / 数据分析工具）填了没。

## 附：六条铁律（写任何一版都生效）

1. 量化一切：有数字写数字，没数字写规模（人数 / 用户量 / 提交数）。
2. 突出贡献：主导 > 负责 > 参与 > 协助——**但只能往真实的那档写**。
3. 对准 JD：投每家前按 JD 调关键词顺序。
4. 删废话：「积极主动」「责任心强」无事实支撑一律删。
5. 永远投 PDF。
6. 一个方向：整份围绕一个求职方向，不让 HR 猜。

## 常见卡点

| 症状 | 处理 |
|---|---|
| 母版缺数字 | 不编。「这块没数字会弱，你能查一下或给个保守区间吗？」 |
| 机主要「夸张一点」 | 「夸张到面试讲不出细节就是反噬，每句话都会被追问」 |
| 差距太大 | 别硬定向，回 jd-decode：「匹配度可能不足以做出有效版本，先决定投不投」 |
| 只想改一段 | 只改那段，但仍走 Step 4/5 |
