# outreach：投递话术与跟进（草稿版，跑完第一个岗后回来修）

触发：岗位卡住了（没回音 / 等排期 / 要探活 / 要问时间安排 / 要找内推）。
产出：**一句可直接复制的话术** + 该不该跟进的判断。投递信走 `email_draft` 落草稿箱。

## 先分清谁发

- **Boss 直聘：她本人手动用，自动化不许碰**（风控封的是她的号）。话术写给她复制。
- **猎聘**：站内沟通，登录态在 Cass 的浏览器；捞岗实操见档案。
- **邮箱**：`email_draft(to, subject, body, resume_id, jd_id)` 落草稿箱，她点发。发送不在工具面上。
- 先 `applications_list` 防重投，再 `profile_get` 读「沟通约定」节——**什么时候问全勤、
  什么时候问弹性，档案定过，别在打招呼阶段问**。

## 打招呼（首次触达）

**核心原则：让对方五秒内知道你是谁、能做什么、为什么找他。**

**Boss / 猎聘站内（50–80 字，超过 100 字 HR 不看完）**
公式：`一句身份定位 + 一句和岗位最相关的亮点 + 一句明确请求`。
档案「自我介绍话术」产品线版是底稿，**末句按公司改成具体的一句**（「看到贵司在做 X 的 0→1」）。
JD 写了「附作品 / 体验报告加分」→ 发完直接补 GitHub 链接。
禁忌：❌「您好我想应聘贵公司 XX 职位，本人有 XX 经验，希望有机会」（零信息量）；
❌ 超过 100 字；❌ 只写「已投简历请查收」；❌ 「贵司」堆出模板腔。

**脉脉 / 找人（80–150 字三段式）**
`为什么找这个人（共同背景 / 他的文章 / 业内认同） + 我是谁最强亮点 + 希望他做什么（具体）`。
请求要具体：帮内推 / 看一眼简历 / 有没有合适岗位。结尾有礼节，不用西式硬跟进腔。

**校友内推**：给台阶（「不方便也完全理解，直接说就好」）；简历放消息里降低对方成本；
只请求内推，不请求说好话。

**邮件投递**：主题 = 岗位 + 姓名 + 学校年级；正文 = 自我介绍话术 + 一句具体的为什么 + 附件说明。
`email_draft` 的 resume_id 必须是已 `resume_render` 过的定向版。

## 跟进节奏

| 状态 | 等多久再动 |
|---|---|
| 投了没回音 | 7 天 |
| 对方回复过 | 3 天内回 |
| 面试之后 | 1 天（感谢 + 一句补充） |
| 跟进两次仍无回音 | 标 cold，建议关掉，别再追 |

**每次跟进必须带一条增量价值**：新做出来的东西、对他们产品的一个真实观察、一个补充材料。
禁空跟进：❌「打扰了想问问进度」❌「不知道简历看了没」——这类只消耗对方好感。
跟进模板（三句）：`提岗位和投递日期 + 一条增量价值 + 软性请求带具体时间窗（「这周方便的话」）`。

## 探活 / 问天数 / 问排期

- 探活（岗位还招吗）：一句，带简历已投的事实，不带情绪。
- 问天数 / 弹性：**只在对方表达兴趣之后**（档案沟通约定）。话术：「想确认一下，这个岗对每周到岗天数
  是硬要求吗？我在读，能保证 X 天，其余时间远程。」全勤三个月以上按档案是扣分不是否决，
  她自己谈。
- 问排期：「方便说一下后续流程和大致时间吗，我这边好安排」——一句，不多。

## 反问面试官

清单在 interview-manual 第 3 节（从 intel 的反问素材出，按 HR / 业务 / 老板分）。**别在这儿重写**，
引过去。好反问的判据：答案会改变你对这个岗的判断，不是显得有准备。

## 落库

- 邮件走草稿箱；站内话术给她复制后，在 `applications.jsonl` 之外的账本（档案「投递现状」节）
  记一行：哪天、哪个渠道、发了什么、等到几号跟进。档案是投递的唯一账本。
- 对方回了 → 转 interview-debrief（面完）或 interview-manual（约了面）。

## 常见卡点

| 症状 | 处理 |
|---|---|
| 她想一次打招呼几十家 | 不海投。jd-decode 三星以下的不发；每条末句都得是具体的 |
| 对方要「先填表」 | 填表不在工具面上，她自己填；把 JD 解码里的关键词给她 |
| 三天没回想再发 | 按节奏表，没到 7 天不动 |
