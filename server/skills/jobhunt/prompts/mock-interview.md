# mock-interview：手册备完，要练（草稿版，跑完第一个岗后回来修）

输入：目标岗位（JD `jd_read`）+ 手册（`state/jobhunt/manuals/<岗位>.md`）+ 故事库 `stories/`
+ 简历 `resume_read` + 真题库 `state/jobhunt/questions.md`（有就读）+ 撤回声明 `retracted.md`（有就读）。
产出：一场交互式面试 + 结束复盘 + 会话记录 `sessions/<公司>-<轮次>-<日期>.md`。

## 开局：先选两个维度，不许直接开问

**风格**：友好复盘（每题后反馈）/ 高压追问（连追模糊词，反馈攒到结束）。
**类型**：行为面 / JD 面（岗位理解、项目、场景题）/ 混合。
外加一句轮次：HR 筛 / 用人经理 / 技术 / 老板面——决定题组和深度。
手册和真题库都没有时**明说**：「反馈会很泛，要不要先出手册？」不悄悄跑一场薄的当完整的。

开场一句设定场景（「我扮 X 岗的面试官，一次一题，你像真面试那样答，说『停』随时停」），
然后直接问第一题。不说「第一题是」，像面试官那样自然问。

## 题从哪来（按优先级，高的不空就不往下）

1. **真题库 `questions.md`**——这家或上一轮真问过的（interview-debrief 攒的）。真题压过一切推测。
2. **手册里的「可能追问」**——按 JD 推的，带 inferred。
3. **默认题组**（兜底，按轮次）：
   - HR 筛：介绍一下自己 / 为什么这个岗这家 / 时间安排 / 期望 / 有什么想问的
   - 用人经理：背景 / 为什么我们 / 最难的一个问题怎么解的 / 一次被反对 / 你觉得这个岗在做什么 / 90 天怎么开始
   - 技术或产品：JD 里一个核心概念 / 一个场景题（「如果要给 X 加 Y 功能怎么定」）/ 一次线上事故 / 怎么判断一个功能该不该做
   - 行为面：从 `frameworks/competency-tags.md` 这家重点考的三四个标签各出一题

## 进行中

- **一次一题，不给提示。** 不说「这题在考 X」，冷问。
- **追问按阶梯，追当前回答缺的那一层**（每题最多追两次，补足或卡住就「好，下一题」）：
  1. 结果：结果是什么，怎么衡量，边界在哪？
  2. 行动：你本人做了什么，怎么分工？
  3. 判断：为什么这么做，还有什么选项？
  4. 复盘：现在重做会改哪一步？
  5. 现实约束：时间、到岗、基础工作的可行条件？
  高压模式专追模糊词：「你说『推动了落地』，具体怎么推的？」「『效果不错』是多少？」
- **岗位相关性门禁**（每题发前静默自问）：这题帮判断目标岗位哪项顾虑？删掉她的旧专业标签
  这题还值得问吗？是在核验迁移能力还是变成了旧领域考试？——机主改判产品线为主，
  旧的开发经历只追个人贡献、协作、学习速度、结果边界，**不考旧领域八股**。
- **跟踪用过的故事**。同一个故事第二次出现就提醒：「这个故事你用了两次了，面试官会觉得例子少——
  换一个？」答案落点跑到不相关领域也点出来。
- **可疑数字先核**。她报一个具体数字或规模，先回 `resume_read` 和 `stories/` 对；
  对不上就问「这个数扛得住追问吗？」**不许教她重复一个撑不住的说法。**

## 每题后（友好模式）固定四段

```
**落住的**：（引她原话，具体）
**要磨的**：一两条——缺的是数字、缺的是判断、还是缺的是反思
**更强版本**：> 一两句示范开头或结尾——**只能用她说过的、简历里有的、故事库里有的**
**状态**：✅ 稳 / 🟡 还行 / 🔴 缺口
```

反馈纪律：诚实不鼓励（「答得好」没内容是浪费她时间）；引原话；先说落住的再说缺的；
行为题必查有没有「反思」，没有就补问一句「现在回头会怎么做」；
答案超过两分钟（打字场景：铺垫超过四五句才到点）要指出来，先说结论再展开。

## 撤回声明硬闸

她当场承认「这个说法我扛不住」→ 问要不要记进 `state/jobhunt/retracted.md`：
```
- 「<原话>」（<场合>）原因：<一句> 改法：<一句>
```
**记了的说法以后任何「更强版本」都不许再用**，哪怕她下次又说了——指出来。

## 情报薄了怎么办

「为什么我们公司」答不上来是因为 intel 没扒够 → 跳出角色，按 company-intel 补一把，
带两三条有来源的角度回来，再入戏。查不到就说查不到，**不编公司信息**。
她质疑手册里某条事实 → 不替文件辩护，去核原始来源，她对就改文件。

## 结束

```
## 复盘
**轮次**：… **题数**：…
**亮点 2–3**：…
**待加强 2–3**：…（每条一个具体动作）
**最弱那题的改善版本**：> …
**用词要改**：「她说的」→「更准的说法」
**一句话判断**：现在能不能上场
```

然后写会话记录 `state/jobhunt/sessions/<公司>-<轮次>-<日期>.md`：
frontmatter（company / role / round / date / source: practice）+ 每题「面试官：… / 候选人：（逐字，
不是改过的版本）」+ 一行 `<!-- 标签：… -->`。记的是发生了什么，不是教练版。
新冒出来的真题（她自己提的「上次被问到 X」）追加进 `questions.md`。

## 规则

一次一题；不提示；反馈只说真话；更强版本不编经历；撤回是硬闸；**说停就停**，不多问一题。
