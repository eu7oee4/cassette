# jd-decode：扒到一条岗，该不该投（草稿版，跑完第一个岗后回来修）

输入：JD **全文**（链接抓不到就要机主贴原文，不许按公司名猜内容）。
产出：解码 + 五件套决策，落 `jd_save` + `jd_score`。是 resume-tailor 和 interview-manual 的前置。

## Step 0 · 先查库（铁律 2）

`jd_list(q=公司名)`：
- 同公司同岗半年内打过分 → 调出来说「上次结论是 ___，直接用还是重解？」
- 同公司不同岗 → 复用隐藏信号和公司层判断，Must Have 重做。
- 没有 → 往下。

顺手 `profile_get` 读档案：地点、方向、优先级、雷点、投递现状全在里面，**硬约束不再问机主**。

## Step 1 · 开正文，别信标题

标题和列表页地点都不可信（档案「猎聘捞岗实操」实测两例）。解码只认 JD 正文的**职责动词**。

## Step 2 · 五图层拆解（按顺序，别跳层）

**① 招聘方真实需求**：把话术翻回「这个人其实想招什么样的人」。格式固定：

```
JD 写：「…」
实际在找：✅ … ✅ … ❌ 不需要 …
```
挑三到五条最关键的翻。查 `frameworks/jd-signals.md` 第一二节。

**② Must Have**（三到五条）：每条**可验证**——看简历能看出来、面试能问出来。
每条一句话 + 为什么是 must（JD 哪里反复出现 / 结构上放在最前）。

**③ Nice to Have**（三到五条）：没有不淘汰，有就加分。

**④ 隐藏信号**：措辞反复出现的词 → 团队想要什么人 → 对简历和手册意味着什么。
三段缺一不写；一个词不算，反复出现才算（jd-signals.md 第四节）。全部 `inferred` 档。

**⑤ 岗位真实形状**：级别（标的 vs 职责暗示的）、团队大小、阶段（0-1 / 1-N / 成熟 / 转型）、
汇报给谁、为什么现在招。**每条标推断依据，不知道写 `unknown`**（evidence-ranking 规则 2）。

## Step 3 · 五件套决策

**① 推荐指数 ⭐ 1–5**，一句话定性。按档案的三级权重综合（压力小假期多 > 兴趣有产出 > 薪资），
不是按匹配度。五星慎给：五星 = 几乎没有 downside。

**② 值得投三条**：具体、可验证。「公司不错」不算。从方向 / 匹配 / 团队 / 学习曲线 / 稀缺性里挑最强的三条。

**③ 不值得投三条（必须给）**：这是五件套的灵魂。级别错位 / 难补的缺口 / 团队动荡 / 入职后真实工作
和 JD 差距 / 跟她第一权重的冲突。真没有三条 → 老实说「我从 JD 看不到明显 downside」，
再列该查的盲区（近况、团队任期、口碑）——不硬凑。

**④ 拿面概率**：**给区间不给单点。** 裸投基线按匹配度（85+ → 30–45%；70–85 → 15–30%；
55–70 → 8–15%；以下不到一成），再乘因子（有内推 ×2 上下、简历定向过 ×1.3–1.5、挂超三个月 ×0.7、
有 deal-breaker 直接砍半）。**永远附「怎么提升」的具体动作。**

**⑤ 下一步**：从「直接投 / 先定向简历 / 先找内推 / 先补一个缺口 / 暂不投 / 先尽调」里挑一两个。

## Step 4 · 打分落库

- `jd_save(source, company, title, text)` 存原文（机主贴的就写「机主贴的」）。
- `jd_score(jd_id, score, reason)`：0–100。**reason 必须写出证据档位**——
  「Must Have 命中 3/4（verified：投递页明写…；partial：…），一条 unknown；雷点：无；
  隐藏信号：结果导向 ×3 → 加班倾向，降一档」。
- 硬 cap（PLAN_jobhunt_skills 第五节）：一条 Must Have 得 0 → 封顶 75；两条 → 封顶 55；
  硬门槛不过（跨城 base、全勤三个月以上且不可谈、学历卡死）→ 直接 archived 并说明。
- **inferred 不进 Must Have 命中判断**，只进「心里有数」。
- 打完分**不自动跑下一步**，问机主：定向简历 / 出手册 / 先归档？

## 有血的一条（2026-08-26）

拿小红书一条帖当官方 JD 给 Bonjour 打了 58 分，第二天读到官方投递页写着「不适合远程」，
翻案成 45。**那次就是把 inferred 当 verified 用。** 所以每个打分理由带档位，不是形式。

## 常见卡点

| 症状 | 处理 |
|---|---|
| JD 太短全是 buzzword | 说清「信息量不够，能解出的有限」，列要补的：公司近期产品方向、团队背景 |
| 只有链接抓不到 | 让机主贴正文。**别按公司名瞎猜** |
| 机主已经决定要投 | 「那直接走 resume-tailor，但先看一眼这三条不值得投，避免盲区」 |
| 机主说「你帮我决定」 | 温和拒：「硬约束和直觉是你的。我能做的是摆清信息——倾向是 ___」 |
| 问「能不能拿到 offer」 | 拿面能估，offer 受面试表现影响太大估了也不准，先把拿面概率最大化 |
