# JD 信号词典：话术翻译 + 隐藏信号 + 红旗（jd-decode 第 1、4 图层查表用）

三个用途：① 把招聘话术翻回真实需求；② 从措辞推断团队想要什么人；③ 认红旗。
**所有推断都是 `inferred` 档**（evidence-ranking 规则 3）：可以写进手册当背景、
决定简历往哪带，**不进 Must Have 命中判断，不当扣分硬理由**。

## 一 · 国内 JD 词典（主战场）

| JD 写 | 真实含义 |
|---|---|
| 拥抱变化 | 需求经常变 / 老板想法多 |
| 结果导向 | 不看过程看结果 / 加班是常态 |
| 抗压能力强 | 压力大、节奏紧（机主第一权重直接冲突，按档案降档） |
| 狼性 / 战斗力强 | 加班 + 强 OKR + 高流动 |
| 主人翁意识 | 期望 ownership，但通常给不了对应权限 |
| 复合型人才 | 一个人当多个人用 |
| 扁平化管理 | 可能真扁平，也可能是「老板直接管 30 个人」 |
| 高速发展期 | 早期 / 业务模式还在变 |
| 0-1 业务 | 没现成 framework，定义工作量大——**对产品线是正命中** |
| 平台型业务 | 成熟 / 螺丝钉风险 |
| 能独立完成 X | 没人带，自己摸 |
| 配合推进 / 沟通协调（无具体动词） | 填空式 JD，招的人自己不知道要什么（档案雷点第一条） |
| 附产品作品 / 体验报告加分 | 对作品集期待高——**直接补 GitHub 链接**，那是最值钱的筹码 |

## 二 · 英文夹词（AI 岗 JD 常混这几个，其余不用记）

| 词 | 信号 |
|---|---|
| ownership / end-to-end / drive | 要全程负责，不能只做一块 |
| ambiguity / unstructured / 0→1 | 找自驱型，没需求文档要自己定义问题 |
| fast-paced / ship fast / scrappy | 节奏快，可能加班，早期阶段 |
| cross-functional / stakeholder | 协作和说服工作量大 |
| data-driven / metrics | 决策要有数据 backing，「我觉得」不够 |
| strong experience with X | 做过 X 一两次能讲清楚就行（不是要 X 年专家） |
| deep expertise in X | 真要多年，且能查证 |
| exposure to / working knowledge | 可有可无 |

## 三 · 红旗表（看到就在解码里点名，进「不值得投」那三条的候选）

| JD 写 | 警惕什么 |
|---|---|
| 「复合型」+ 列了五个以上职责 | 一个人当三个用 |
| 「抗压」「狼性」「福报」 | 加班文化 |
| 「像家一样」「兄弟」 | 边界模糊，加班文化换个说法 |
| Must Have 写了十条以上 | 用人方不知道要什么，简历筛得随机 |
| 挂了半年还在招 | 内部对岗位 / 级别 / 薪资有分歧，面试容易反复 |
| 薪资范围跨度极大 | 级别含糊，压价风险 |
| 学历门槛低 + 薪资畸高 | 保险 / 医美 / 贷款 / 培训费（档案雷点） |
| 招聘主体 ≠ 落款公司 | 外包 / 子壳（档案雷点） |
| 岗位实质 = 拖 Coze/Dify 流程 + 写体验报告 | 学不到东西，降档；但「不写代码」本身不是雷点 |

## 四 · 三条查表纪律

1. **标题和列表页地点都不可信，看职责动词**（档案「猎聘捞岗实操」实测：讯飞挂杭州实为合肥、
   伊阁挂「AI 工作流开发」实为产品岗）。解码前必须开 JD 正文。
2. **一个词不构成信号，反复出现才算**。JD 里「拥抱变化」出现一次是模板，出现三次加「抗压」
   才写进隐藏信号。
3. 信号写法固定：「JD 反复出现 X → 信号：Y → 对手册/简历意味着：Z」，三段缺一不写。
