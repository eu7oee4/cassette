# 讲故事的框架：STAR / CAR / SOAR + 黄金配比 + 一稿多用

## 三个框架，何时用哪个

| 框架 | 结构 | 最适合 |
|---|---|---|
| **STAR** | 背景 · 任务 · 行动 · 结果 | 默认主力。绝大多数行为题都用它。库里按它存全料。 |
| **CAR** | 挑战 · 行动 · 结果 | 要更短、更快入题：电话初筛、HR 面、追问里的补充。省掉冗长背景。 |
| **SOAR** | 背景 · 障碍 · 行动 · 结果 | 题目点名「最大挑战」「克服困难」「压力下」时，把障碍单拎出来讲。 |

经验法则：**库里按 STAR 存全集，临场按题型裁成 CAR / SOAR。** 存的是全集，讲的是子集。

## 黄金配比（口述 60–90 秒，中文约 200–280 字）

```
背景 S  ▓▓         ~15%   一两句，听懂即可
任务 T  ▓▓         ~15%   锁定「我」的责任，不是「我们」
行动 A  ▓▓▓▓▓▓▓    ~50%   引擎：讲判断和取舍，不是流程
结果 R  ▓▓▓        ~20%   数字 + 一句「我从中带走了什么」
```

最常见的死法是背景讲一半时间、行动只剩一句。**时间预算永远向 A 倾斜。**
第二常见：结果只报数字不报反思。「重来会改哪一步」是面试官分辨「做过」和「想过」的那句。

## 一稿多用：同一个故事打 5–8 道题

一个挖透的故事换**开场句 + 落点**就能打不同的题，主体 A 不动。
例：「一个化简提议没被采纳，却让方案改好了三处」（scene-merge-question）——

| 被问到 | 开场往哪带 | 落点强调 |
|---|---|---|
| 怎么 review 一个设计 | 强调我先质疑的是分类不是细节 | 三处改动怎么来的 |
| 一次改变主意 | 强调最初的提议被否 | 为什么否得对 |
| 处理不同意见 | 强调分歧点在哪 | 怎么把分歧变成改进 |
| 抽象能力 | 强调「历史包袱 vs 硬理由」 | 说得出的理由才留 |
| 最大的失败（若算） | 强调早期误判 | 复盘与改变 |

**所以打标时一定告诉机主「这个故事还能打哪些题」**——这是故事库复用价值的直观证明，
也是铁律 2「先查库」能成立的前提。

## 讲的时候（口述版纪律，story-mining 三条纠偏同样生效）

- 不凹金句，念一遍像饭桌上会说的话。
- 数字说不准就说「大概」，不说精确到个位的假数。
- 归属诚实：哪部分是 AI 给的、哪部分是自己判断的，说清楚反而加分。
