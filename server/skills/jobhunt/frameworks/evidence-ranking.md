# 证据分级与硬 cap（打分/写手册/比岗位前必读）

> 这条是有血的：08-26 拿小红书一条帖当官方 JD 给 Bonjour 打了 58 分，第二天读到
> 官方投递页写着「不适合远程」，翻案成 45。**那次就是把 `inferred` 当 `verified` 用。**

## 四档证据

| 档位 | 判据 | 例 |
|---|---|---|
| `verified` | 官方一手：官方 JD / 投递页 / 官网 / 机主亲历 | 投递页明写「坐班杭州」 |
| `partial` | 官方来源但间接/过时，或两个独立二手互证 | 半年前的官方招聘稿 |
| `inferred` | 二手推断：小红书帖、脉脉、面经、「同类公司一般如此」 | 帖子说「他家加班狠」 |
| `unknown` | 没有任何来源 | 没查到薪资范围 |

## 规则

1. **逐字段判，不是逐岗判。** 一个岗位的「技能要求」可以 verified、「薪资」同时
   unknown——档位跟着字段走，写在字段旁边。
2. **`unknown` 永远不许变成一个看着合理的值。** 不知道就写 `unknown`，
   不许用「大概」「应该」补位。Never convert unknown into a plausible value.
3. **降档使用**：inferred 的信息可以写进手册当背景，但**不许**参与打分里的硬性判断
   （Must Have 命中与否只认 verified/partial）。
4. **来源落款**：每条 intel、每个打分依据都带「来源 + 档位 + 日期」，翻案的时候
   才知道当初信的是什么。

## 硬 cap（打分时机械执行，不许「综合感觉」豁免）

- 一条 Must Have 得 0 分 → 匹配度**封顶 75%**
- 两条 Must Have 得 0 分 → **封顶 55%**
- 硬门槛不过（学历/坐班城市/证书这类非商量项）→ **直接移出主列表**，不用打分
